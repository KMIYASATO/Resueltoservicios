# 1. FUNDAMENTOS DE MARCA

## 1.1 Nombre

# Resuelto

El nombre expresa el resultado que busca el usuario: dejar de preocuparse porque el problema ya está siendo atendido.

No presenta a la marca como un directorio de técnicos. La presenta como una plataforma que acompaña el proceso completo:

```text
Necesidad → búsqueda → comparación → reserva → atención → pago → confirmación
```

## 1.2 Descriptor

Usar debajo del logotipo o en contextos donde la marca todavía no sea reconocida:

> **Servicios de confianza, cuando los necesitas.**

Alternativa corta para espacios reducidos:

> **Servicios a domicilio.**

## 1.3 Promesa de marca

> Resuelto te ayuda a encontrar, comparar y reservar profesionales confiables desde un solo lugar.

## 1.4 Idea central

> **Tu problema ya está encaminado.**

Esta idea debe guiar el diseño, la comunicación y la experiencia. La interfaz debe reducir estrés y transmitir control.

## 1.5 Posicionamiento

Resuelto es un marketplace peruano de servicios a domicilio que permite comparar profesionales, revisar reputación, conocer precios, reservar horarios y gestionar el servicio de forma clara y segura.

## 1.6 Diferenciación

Resuelto no es:

- un clasificado de números telefónicos;
- un directorio sin seguimiento;
- una página de anuncios;
- una ferretería digital;
- una empresa que ejecuta todos los servicios directamente.

Resuelto sí es:

- una plataforma de descubrimiento;
- un sistema de comparación;
- un gestor de reservas;
- una herramienta de reputación;
- un canal de pago y seguimiento;
- un sistema de gestión para profesionales.

# 2. PERSONALIDAD DE MARCA

## 2.1 Atributos principales

| Atributo | Qué significa en la experiencia |
|---|---|
| Confiable | Información clara, profesionales identificables y procesos visibles. |
| Resolutiva | La interfaz lleva al usuario a una acción concreta. |
| Cercana | Lenguaje natural, directo y peruano sin caer en exceso de informalidad. |
| Serena | No amplifica el estrés del usuario. |
| Moderna | Diseño digital actual, limpio y rápido. |
| Transparente | Precios, condiciones y estados explicados antes de confirmar. |

## 2.2 Arquetipo

**Cuidador resolutivo + guía.**

La marca acompaña, organiza y ayuda a elegir. No presume superioridad ni utiliza un tono agresivo.

## 2.3 Principios de experiencia

1. **Primero la claridad.**
2. **Una acción principal por pantalla.**
3. **Menos incertidumbre, más estados visibles.**
4. **La confianza se demuestra con información, no con frases vacías.**
5. **El usuario siempre debe saber qué sigue.**
6. **La urgencia se atiende sin generar alarma.**

# 3. IDENTIDAD VERBAL

## 3.1 Tono de voz

El tono debe ser:

- directo;
- cálido;
- tranquilo;
- útil;
- sencillo;
- humano.

## 3.2 Forma de escribir

### Sí usar

- verbos de acción;
- frases breves;
- lenguaje cotidiano;
- instrucciones concretas;
- mensajes orientados a solución;
- términos comprensibles para usuarios no técnicos.

### Evitar

- tecnicismos innecesarios;
- frases corporativas;
- superlativos sin sustento;
- humor en situaciones de emergencia;
- culpabilizar al usuario;
- mensajes ambiguos;
- palabras como “ecosistema”, “disrupción”, “sinergia” o “solución 360” en la interfaz.

## 3.3 Ejemplos correctos

**Hero:**

> Encuentra al profesional que necesitas, sin complicaciones.

**Búsqueda:**

> ¿Qué necesitas resolver?

**Disponibilidad:**

> Disponible hoy desde las 3:00 p. m.

**Reserva confirmada:**

> Tu servicio quedó reservado.

**Profesional en camino:**

> Carlos está en camino. Llegará aproximadamente en 25 minutos.

**Error de pago:**

> No pudimos procesar el pago. Revisa los datos de tu tarjeta o prueba con otro medio.

## 3.4 Ejemplos incorrectos

- “Conectamos oferta y demanda mediante una experiencia disruptiva”.
- “Somos la mejor plataforma del mercado”.
- “Ups, parece que rompiste algo”.
- “Error 403: operación denegada”.
- “El proveedor ha iniciado el desplazamiento hacia la geolocalización indicada”.

## 3.5 Vocabulario recomendado

| Usar | Evitar |
|---|---|
| Profesional | Recurso |
| Servicio | Orden de trabajo, salvo contexto administrativo |
| Reserva | Ticket |
| Precio estimado | Cotización definitiva, si puede variar |
| En camino | Desplazándose |
| Necesitamos confirmar | Validación requerida |
| Resolver | Gestionar incidencia |
| Ayuda | Mesa de soporte |
| Dirección | Geolocalización del requerimiento |

## 3.6 CTAs principales

- Buscar profesionales
- Ver profesionales
- Reservar ahora
- Continuar
- Confirmar reserva
- Elegir horario
- Solicitar servicio
- Ofrecer mis servicios
- Ver disponibilidad
- Contactar soporte

No usar más de un CTA primario por bloque.

# 5. LOGOTIPO

## 5.1 Concepto recomendado

El símbolo debe representar:

- resolución;
- llegada;
- ubicación;
- confirmación;
- tranquilidad.

Dirección recomendada:

> Un isotipo original que combine un check con una forma de ubicación o trayecto, sin copiar el pin de otras plataformas.

## 5.2 Composición

### Versión principal

```text
[ISOTIPO] Resuelto
          Servicios de confianza, cuando los necesitas.
```

### Versión compacta

```text
[ISOTIPO] Resuelto
```

### Isotipo

Uso en:

- favicon;
- ícono de app;
- avatar de redes;
- loader;
- identificador compacto.

## 5.3 Estilo del wordmark

- tipografía base: Manrope;
- peso sugerido: 700;
- minúsculas con inicial mayúscula: `Resuelto`;
- apariencia geométrica, limpia y ligeramente redondeada;
- evitar itálicas y efectos 3D.

## 5.4 Área de seguridad

Usar como espacio libre mínimo alrededor del logo una distancia equivalente a la altura de la letra “R” del wordmark.

Ningún texto, borde o imagen debe invadir esta área.

## 5.5 Tamaños mínimos

| Uso | Tamaño mínimo |
|---|---:|
| Logo horizontal digital | 120 px de ancho |
| Isotipo digital | 24 × 24 px |
| Favicon | 32 × 32 px |
| Ícono de app | 512 × 512 px maestro |

## 5.6 Versiones autorizadas

- azul sobre fondo blanco;
- blanco sobre fondo azul;
- monocromático negro;
- monocromático blanco;
- isotipo azul;
- isotipo blanco.

## 5.7 Usos prohibidos

No:

- deformar;
- rotar;
- aplicar degradados no aprobados;
- usar sombras fuertes;
- cambiar colores;
- encerrar en formas no definidas;
- reemplazar el wordmark por otra tipografía;
- agregar herramientas como martillos o llaves inglesas;
- copiar el estilo de logotipo de Webel.

## 5.8 Logo temporal para desarrollo

Mientras no exista el archivo final del logotipo, OpenCode deberá crear un **placeholder original**, simple y claramente reemplazable.

Requisitos:

- SVG propio;
- check abstracto;
- fondo azul;
- sin copiar marcas existentes;
- componente separado;
- nombre sugerido: `ResueltoLogo`.

- selección activa debe incluir color, borde o indicador adicional.

# 11. FOTOGRAFÍA E IMÁGENES

## 11.1 Dirección fotográfica

Mostrar:

- profesionales reales;
- hogares luminosos;
- interacción natural;
- diversidad de edades;
- situaciones creíbles;
- uniformes o vestimenta limpia;
- herramientas solo cuando sean relevantes;
- contexto peruano o latinoamericano cuando sea posible.

## 11.2 Evitar

- fotografía de stock evidentemente posada;
- exceso de herramientas;
- fondos industriales;
- imágenes oscuras;
- situaciones de riesgo;
- estética de construcción pesada;
- personas mirando siempre a cámara;
- fotos copiadas de Webel.

## 11.3 Tratamiento

- luz natural;
- color cálido y neutral;
- contraste moderado;
- esquinas redondeadas;
- evitar filtros saturados;
- usar overlays muy suaves.

## 11.4 Contenido simulado

Durante el prototipo:

- marcar testimonios como demostrativos;
- usar nombres ficticios claramente indicados;
- no presentar métricas inventadas como reales;
- centralizar mocks en archivos de datos.

- sin fondo;

```text
Altura: 52 px

```

Estados:

- disabled.

## 14.5 Buscador principal

Debe combinar:

1. servicio;
2. ubicación;
3. CTA.

Desktop: horizontal.  
Mobile: vertical.

Debe ser el elemento más visible del hero.

## 14.6 Cards de servicio

Contenido:

- imagen o ícono;
- nombre del servicio;
- precio referencial si aplica;
- microcopy;
- enlace o CTA.

Comportamiento:

- toda la card es clicable;
- hover sutil;
- foco visible;
- no usar más de tres líneas de descripción.

## 14.7 Card de profesional

Debe mostrar como mínimo:

- fotografía;
- nombre;
- insignia de verificación;
- especialidad;
- valoración;
- número de reseñas;
- servicios completados;
- precio desde;
- disponibilidad;
- CTA “Ver perfil”.

Datos secundarios opcionales:

- clientes recurrentes;
- zona;
- atención urgente;
- tipo de profesional.

## 14.8 Badges

Tipos:

- Verificado;
- Disponible hoy;
- Recomendado;
- Respuesta rápida;
- Nuevo;
- Servicio completado.

Deben incluir texto, no solo color.

## 14.9 Alertas

Tipos:

- info;
- success;
- warning;
- error.

Estructura:

```text
[ícono] Título breve
        Explicación concreta
        Acción opcional
```

## 14.10 Modales

- ancho máximo: 560 px;
- radio: 20 px;
- overlay oscuro al 40%;
- cierre visible;
- foco atrapado;
- Escape cierra cuando no sea crítico;
- CTA principal alineado a la derecha en desktop y full width en mobile.

## 14.11 Toasts

- duración: 4–6 segundos;
- no usar para información que el usuario deba conservar;
- incluir acción “Deshacer” cuando aplique.

## 14.12 Skeletons

Usar durante cargas de:

- resultados;
- perfiles;
- reseñas;
- reservas;
- dashboard.

Evitar spinners como única señal de carga en páginas completas.

# 20. CRITERIOS DE ACEPTACIÓN PARA OPENCODE

- utiliza “Resuelto”;
- usa el descriptor aprobado;

- el naranja se reserva para CTA;
- los estados usan colores semánticos;
- cumple contraste AA.

## Tipografía

- Manrope para display;
- Inter para UI;
- escala consistente;
- no usa tamaños arbitrarios.

## Layout

- mobile-first;
- contenedor máximo 1280 px;
- grid consistente;
- espaciado basado en múltiplos de 4.

## Componentes

- reutilizables;
- accesibles;
- todos los estados definidos;
- ningún botón sin acción;
- focus visible;
- loading, empty y error.

## Contenido

- textos originales;
- mensajes concretos;
- testimonios simulados identificados;
- no incluye métricas falsas como reales.

## Código

- TypeScript estricto;
- design tokens centralizados;
- componentes separados de datos mock;
- sin secretos;
- sin copiar HTML/CSS de terceros;
- estructura modular;
- sin valores visuales repetidos en línea cuando deban ser tokens.

# 21. USOS INCORRECTOS DE LA MARCA

No aprobar diseños que:

- usen rojo como color principal;
- parezcan ferretería;
- usen iconos de martillo y llave como identidad central;
- tengan fondos oscuros en toda la web;
- utilicen muchos degradados;
- mezclen más de dos familias tipográficas;
- oculten precios o condiciones importantes;
- muestren demasiados CTAs naranjas;
- usen lenguaje técnico;
- presenten contenido ficticio como real;
- copien la estructura visual exacta de Webel.
